# 阶段四：自动质量检查

> 当前每日 pipeline 默认执行固定样例回归与当天规则检查，详见 [Pipeline 运行说明](../Pipeline运行说明.md)。本页独立 QA 命令仍为同一期比较；下方分阶段验收数字及策略阻断是历史记录。

自动 QA 检查已入库原稿与其最终 HTML，生成 JSON、可读报告及三种视口截图。正文完整性通过重新渲染原稿后的语义文本比较核对；图片实际解码；目录、材料和锚点对应 manifest。外链仅核对格式，不联网验证活性。CSS、图片和摘录必须可独立阅读。

## 安装与新目录布局

保留 `src/publisher/`、根目录 `templates/` 和 `tests/`；运行产物集中在 `outputs/`。在项目根目录执行：

```bash
source ~/miniconda3/etc/profile.d/conda.sh
conda env create -f environment.yml
conda activate daily-input
python -m playwright install chromium
# 以下命令需要 sudo；仅在获得用户授权后于本机终端执行
python -m playwright install-deps chromium
python -m pip check
```

`pip install -e .` 为源码原位安装；本次交付面向从仓库运行，正式模板仍读取根目录 `templates/`，并未制作可脱离仓库的 wheel 分发包。阶段三入库、出版命令在安装后继续使用原来的 `python -m publisher.ingest` 与 `python -m publisher`。

## 一期 QA 与视觉基线

下列命令须先激活 daily-input conda 环境。第一次建立基线必须先运行普通 QA 获取截图、审阅后再明确指定 `--update-baseline`：

```bash
python -m publisher.qa outputs/stage4/nine/issues/2026-11-06 \
  --html outputs/stage4/nine/html/Daily_Input_2026-11-06.html \
  --output-dir outputs/stage4/nine/qa \
  --baseline-dir outputs/stage4/nine/baseline --update-baseline
```

之后比较同一期成品：

```bash
python -m publisher.qa outputs/stage4/nine/issues/2026-11-06 \
  --html outputs/stage4/nine/html/Daily_Input_2026-11-06.html \
  --output-dir outputs/stage4/nine/compare \
  --baseline-dir outputs/stage4/nine/baseline
```

缺少基线会失败；普通比较不会改写基线。只有静态检查和真实浏览器检查全部通过，显式更新才写入基线。基线是该稿件在固定浏览器和字体环境的视觉参考，换内容、模板、浏览器或字体时应审阅截图后明确更新。初次创建记录为 `visual.details.mode=created`，比较记录为 `compared`。像素颜色差值超过16的像素计为变化，比例超过0.1%或截图尺寸变化时阻断，并保留差异说明与可生成的差异图。

浏览器固定使用真实 Chromium，断网加载本地文件；三视口为390×844、820×1180、1180×820。检查整页无横向溢出、图像解码、内链目标以及正文20px/31px，并保存完整页面 PNG。长表格和长代码允许组件内滚动。截图与视口模拟使用 [Playwright截图接口](https://playwright.dev/python/docs/screenshots) 和 [设备模拟接口](https://playwright.dev/python/docs/emulation)。这些是 Chromium 视口模拟，不等同真实 iPad Safari 或 Windows Chrome 验收。

有既有浏览器文件时可提供 `--browser-executable /absolute/path/to/chrome-headless-shell`。缺少 Playwright、浏览器或运行依赖时明确失败，绝不会跳过浏览器后写通过。`--max-bytes` 可改成品体积上限，默认12MiB。

## 报告与示例

每次在输出目录写 `report.json` 与 `report.md`，总状态为 `passed` 或 `failed`；检查项固定为 content、structure、media、links、html、package、browser、visual。阻断项失败时退出码1，全部通过退出码0。静态不通过时 browser/visual 记录为 not_run，且总结果为失败。

- [九栏十篇成品](../../outputs/stage4/nine/html/Daily_Input_2026-11-06.html)：沿用阶段三馆藏图、表格、代码、引文与摘录。
- [长短混合作者稿](../../outputs/stage4/author-long/Daily_Input_2026-11-07.md)：九栏十篇，包含多张真实随期图片、多小节、连续长文、十二列表格、千字符代码长行、中英文和公式字符。
- [长文成品](../../outputs/stage4/long/html/Daily_Input_2026-11-07.html)：与九栏样例使用独立基线，运行命令对应改成 long、日期2026-11-07。
- [常见失败的作者稿目录](../../outputs/stage4/author-errors/) 与 [失败 HTML 目录](../../outputs/stage4/invalid-html/)：缺图、断链、空文件和截断稿。用九栏入库期作为 `ISSUE`，将 `--html` 改为其中的失败 HTML，报告会阻断。

复跑长文生产：

```bash
python -m publisher.ingest outputs/stage4/author-long/Daily_Input_2026-11-07.md \
  --metadata outputs/stage4/author-long/issue.json --store outputs/stage4/long/issues \
  --output-dir outputs/stage4/long/html
```

公式样例保留原稿中的 Unicode 数学表达式与文字；本阶段没有引入联网字体或 MathJax。浏览器与测试最终验收记录另行补充。阶段四不发送邮件，不部署云端，也不修改既有定时任务。

## 2026-11-07 WSL 环境迁移

独立环境名为 `daily-input`，由根目录 `environment.yml` 管理 Python 3.12、
出版依赖、Playwright 和现有邮件 OAuth 配置工具。修改依赖后执行
`conda env update -f environment.yml`，再运行 `python -m pip check`。
旧 `.venv` 保留，不自动删除或替换。

本次 WSL 检查确认 Chromium 缓存已存在，但缺少
`libnspr4.so`、`libnss3.so`、`libnssutil3.so`、`libasound.so.2`。
这是浏览器启动阶段的运行库问题；此前受限执行器的 socket 权限问题属于另一种环境阻断。
conda 负责 Python 依赖；上述 Chromium 原生运行库由 Ubuntu 管理，不能只靠 pip 安装修复。
用户已在本机完成系统依赖安装；Chromium 动态库现已全部解析，实际启动成功。sudo 密码只应在本机终端输入，不能在聊天中提供。

安装依赖后，先使用本文普通 QA 命令对已有九栏与长文示例比较，保持原基线不变。
浏览器可启动但视觉比较失败时，应查看截图、差异图和字体环境；
不得为消除差异自动加 `--update-baseline`。
QA 报告的各视口现记录实际 Chromium 版本，便于识别环境变化。
新一期内容应使用独立、经审阅的基线，不可沿用另一日报的整页截图。
