# 每日视觉门禁：已批准并实现

用户已同意“固定两份已确认样例做模板回归；每天不同内容执行规则检查并保留截图”的自动交付策略。pipeline 默认 `--visual-policy daily`，不再要求每日新稿与旧期整页基线相同。此前关于“策略尚未确定”的段落是批准前的历史记录。

每次运行先使用当前模板重新出版固定九栏、长文样例，比较其已批准基线并核对稿件、截图哈希和字体环境；之后对本期执行内容、结构、媒体、链接、HTML、离线包及三视口浏览器规则检查，保存三张整页截图。任一固定回归或本期规则失败均停止归档及邮件处理。每日模式不读取、创建或更新本期基线；同一期比较仍可显式选择 `--visual-policy same-issue --baseline-dir ...`。

这项授权确定了自动技术门禁标准，不表示每期通过人工审美验收。运行与 QA 报告均标明 `human_visual_review=not_performed`；每日整页比较项标为 `not_applicable`，并明确保留截图。两份固定样例仍必须全部比较通过，不能把 `not_applicable` 当作固定回归通过。

11 月 4 日真实试刊按新策略已完成回归、规则、归档和 EML 预览；该期旧生产基线未修改，也没有被追认批准。实测及命令见[Pipeline 运行说明](../Pipeline运行说明.md)。真实 Gmail 发送仍需独立的具体授权，本次没有发送。

## 以下为策略批准前的机制与调查记录

# 每日内容变化时的视觉验收

整页截图基线适合“同一期、同一版本、同一份 HTML”的回归，
不适合把昨日整页拿来验收今日内容。新闻篇数、标题长度、图片和文章长度都会改变长截图。
一次字体选择只能确定风格，不能自动批准尚未审阅的每期版面。

## 当前机制与修复

当前普通 pipeline 要求八项 QA 全通过，其中包含同一期截图比较。
首次没有本期基线会在 visual 阶段失败，因此当前程序不能仅靠旧基线实现每日不同内容的无人值守验收。
不能通过把 `--update-baseline` 常驻到定时任务中消除这个阻断。

新生成的基线记录日期、版本、manifest SHA-256、HTML SHA-256 和各截图 SHA-256：
不同日期、同版本内容变动、HTML 或 CSS 变动不能复用原基线。
参考 PNG 与登记哈希不符时，先报告基线完整性错误，不再误报成正常视觉比较。
QA 输出目录和基线目录不得相同或相互包含，路径冲突在写报告或截图前拒绝。
这避免普通检查先覆盖参考图片，再把新图和自己比较。

旧基线缺少身份与哈希时，保持原样，仍按旧像素比较逻辑处理；
不自动迁移、推断人工批准或将历史基线改成当前图。
两份已由用户确认的九栏、长文示例只补登记了现有身份与哈希，PNG 未因该修复重写。

## 建议的日常流程

1. 固定的九栏与长文样例用于字体、模板和组件的截图回归；
   比较它们的已批准基线，检测设计系统变化。
2. 每期新稿独立执行内容、结构、图片、离线资源和多视口浏览器规则检查，保存完整截图。
3. 在隔离候选目录生成该期审阅材料，记录原稿、HTML、环境和图片哈希。
   技术检查通过只表示程序检查通过，不表示人工视觉审阅已完成。
4. 审阅者确认该期和具体 HTML 后，再建立其正式基线，使用普通比较复验，
   后续归档、邮件使用同一份 HTML 字节。

基线创建命令的 `mode=created`、QA 的 `passed` 都不是人工审批证明。
当前程序没有签名审批服务；`approval` 元数据用于记录审阅证据，不应被当成自动验证用户同意的机制。
本次没有改变 pipeline 的批准策略，也没有创建发送授权。

如果产品目标是每日完全无人值守，需要用户另外明确允许的策略：
用固定样例回归加本期规则检查自动交付，并仅对异常安排人工审阅，
同时保留全部截图和哈希。它与“每期人工审阅后交付”是不同的验收标准。
在此策略尚未确定前，保留现有视觉阻断，不自动绕过或批准。
