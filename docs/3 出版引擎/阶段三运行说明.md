# 阶段三：作者稿到单文件 HTML

本次交付新增作者稿入库入口，沿用正式 Jinja2 模板。九栏十篇示范包含《牛轭湖》原图、表格、代码、引文与本地摘录；样文明确标为构造案例。程序不研究新闻、不改写正文、不联网取图、不发送邮件。

## 安装与运行

在项目根目录使用 Python 3.10 以上版本（本次使用 Python 3.12）：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m publisher.ingest \
  'docs/3 出版引擎/作者交稿示例/Daily_Input_2026-11-06.md' \
  --metadata 'docs/3 出版引擎/作者交稿示例/issue.json' \
  --store /tmp/daily-input-inbox --output-dir /tmp/daily-input-html
```

已入库的稿件可独立重跑出版：

```bash
.venv/bin/python -m publisher /tmp/daily-input-inbox/2026-11-06 \
  --output-dir /tmp/daily-input-html --max-edge 1600 --max-bytes 12582912
```

作者交付普通 Markdown、同目录的 `assets/` 和期次信息 `issue.json`。信息中必填 `date`、非空字符串 `version`、`sections`；九栏名称对应 `topic`（当期主题）和 `digest`（目录提要）。完整格式见 [示例元数据](作者交稿示例/issue.json)，正文见 [九栏十篇作者稿](作者交稿示例/Daily_Input_2026-11-06.md)。作者不维护 manifest，不分配 ID，不创建 READY。所有来源须已由作者核对；程序保留来源记录，不代替事实和许可审核。

## 入库结果与修订

`STORE/2026-11-06` 是指向 `.revisions/2026-11-06/输入摘要/` 的相对符号链接。每个修订完整保存 `original.md`（作者稿原字节）、`issue.json`、带标记的 `Daily_Input_2026-11-06.md`、`manifest.json`、原图及最后写入的 `READY`。READY 绑定文件 SHA256。日期锁串行提交；通过原子链接替换使出版程序一次只看到同一版。旧修订保留，可追溯来源和停用编号。需要支持符号链接、`flock` 和原子改名的 Linux 文件系统。

同一输入和同一版本重试复用已提交修订；同一版本改稿报错。修订时复制上版工作副本及 assets 作为新交稿，修改 `version`，保留对象前的 ID 标记。改题、换序、跨栏移动时携带标记；复制为新篇时删除复制块中的标记，程序发新号。删除对象的 ID 留在 manifest 的 `retired` 中，不重复使用。栏目改名仍沿用原栏目身份及 A/B 归属；A 版三栏须在 B 版六栏前。文章来源位置以版别决定，与体裁无关。

替换稿丢失标记时只自动匹配全局唯一的同类型、同名对象。无法唯一判断的对象报告行号和候选 ID，不猜测。编辑可在元数据的 `identity` 提供行号到既有 ID 的映射，例如 `{"17":"art-002"}`；明确是新对象时填 `null`。行号按此次交稿的原始行号计算。首次导入旧文档，可用此映射保留 `requests`、`processing`、`material-1` 等真实旧锚点；已带标记的首次旧稿须通过 `legacy_ids` 白名单显式授权导入。

## 本地摘录与旧资料链接

材料出处中的 `[原件摘录](excerpt:record-key)` 对应元数据：

```json
{"excerpts":{"record-key":{"title":"本项目记录 · 2026-11-06 · 章节","text":"可离线阅读的原文摘录。"}}}
```

每个材料可引用多份摘录。程序分配 `src-mat-001`、`src-mat-001-002` 等稳定 ID，并生成返回材料链接。删去摘录后其后缀留存。摘录文字按 Markdown 行内规则渲染；段落、材料仍按原稿规范提交。

公开资料链接直接保留；本期 `#ID` 和 `Daily_Input_YYYY-MM-DD.html#ID` 形式的旧归档链接可保留。指向项目目录的旧相对资料链接须通过元数据 `links` 显式映射为本期锚点或公开 URL，例如 `{"../old.html":"https://example.org/original"}`。材料来源中的旧链接也可映射到 `excerpt:record-key`，以随文嵌入摘录，避免成品依赖项目目录。

## 故障与验收

校验失败不提交；提交前中断不替换上一版。出版程序将 HTML 写入临时文件，通过体积及链接校验后原子替换已有成品，失败保留原 HTML。重试按原命令执行，保留的旧修订和孤立候选不需要作者手工修改。

自动测试入口：`.venv/bin/python -m unittest discover -s tests -v`。独立测试报告与 Reviewer 记录由对应 agent 汇总；浏览器离线冒烟由主 agent 检查。系统化浏览器质量检查归阶段四，Gmail 与真实 iPad 附件体验归阶段六。本次未新增游戏截图；游戏栏目使用明确标注的构造样文，已核实馆藏图覆盖实际图片交付链路。
