项目根目录为 `/home/lya3106643285/projects/daily-input`。日期、内容版本、当期主题和目录提要需要有明确输入；入库程序拥有清单的维护权。当前样例把这些值放在清单中，作者侧以何种简洁方式交付期次信息、当期主题和提要，由 Build 定义并记录。不得要求写作者手填清单、分配 ID 或创建 READY。

### 写作骨架的用法

骨架只保留刊名、九个二级栏题和可复制的三级文章块，遵循现有解析层级。前三栏归 A 版（AI 前沿、硬件/图形与价格、科技与游戏事件），后六栏归 B 版（论文精读、GitHub 经典项目、GitHub 特殊新项目、Gaming 技术解读、游戏推荐、每日好图）。入库程序按栏目身份映射到 A/B。版别标题由 HTML 模板生成，避免在 Markdown 中多插一级标题。

把占位文字【…】替换成正式内容；同栏多篇时复制整块，每篇按实际体裁填写“新闻摘要”或“讲解综述”。可在栏题下写导语，用四级标题组织篇内段落。图放在要读者看到它的位置，按“图片、图注、材料出处”顺序交接，路径相对于本期目录。每日好图栏给出了可复制的图片块，其他栏也可使用。骨架中的提示不进入成品。写作与媒体协议见[原稿规范](<../1.5 Markdown 原稿规范/Markdown_Content_Spec_V1.0.md>)、[媒体规范](<../1.6 媒体内容协议/Media_Asset_Spec_V1.0.md>)和[九栏组织建议](<../2 HTML 设计系统/日报各版块的组织形式.md>)。

## 复现已有基线

在项目根目录、安装了 requirements.txt 所列依赖的 Python 环境运行：

```bash
python -m publisher 'docs/3 出版引擎/示例期' --output-dir /tmp/daily-input-review
```

交接前复核：示例连续运行两次，所得 HTML 与仓库样刊逐字节一致。原 JPEG 为 4000 × 2733、3,053,431 字节；内嵌 JPEG 可解码，为 1600 × 1093、270,984 字节，整份 HTML 为 369,820 字节。已有产物时把 `--max-bytes` 设为 1，程序报错退出，原成品内容完整。默认长边 1600 px、成品上限 12 MiB 是原型的可调参数。含真实配图的整期在 iPad Gmail 中的清晰度与附件体验仍需实测。

## 阶段三剩余工作与验收顺序

1. **从作者稿入库（3.1–3.3、3.6）。** 做出正式入口，从普通九栏稿和期次信息生成工作副本、清单与 READY。校验重复栏目、标题层级、缺失来源、图片引用和占位文字。首次入库、同版重试和同日修订要可区分。验收时让九栏中至少一栏有两篇，并验证作者原件字节不变。
2. **稳定身份与恢复（3.3、3.6、3.9）。** 按 1.7 实现新增、重命名、换序、跨栏移动、删除留号及旧锚点导入。遇同名或标记丢失且无法唯一配对时报告具体对象。同日期串行提交；模拟中断与并发重试，验证工作副本与清单同版可见，失败保留上一版，旧链接仍能定位。
3. **核对解析和编排（3.2、3.4、3.7）。** 对照两份现有协议跑通正文、栏目导语、多来源、表格、代码、引文、图片和本地摘录往返。用同体裁跨 A/B 的稿件检查两种来源位置。错误输入给出期次、所属文章和原稿位置。重点补齐本地摘录与旧资料链接的处理，分别以组件样例和正式整期做回归。
4. **接通图片与单文件交付（3.5、3.8、3.10）。** 入库从实际引用建立素材记录，保留来源与许可依据。覆盖 JPEG、透明 PNG、WebP、多图、长图、方向标记、重复引用；缺失、损坏、越界路径和超限要可诊断。验证原图保留、阅读副本离线可解码、图注与出处对应、整期体积受控。游戏截图使用已核实可刊用的真实素材；《牛轭湖》可沿用样例。
5. **交付阶段三可复跑的结果。** 给出安装和执行入口、作者交稿示例、入库产物及九栏含图 HTML；记录上述正例、失败和恢复用例。窄屏、iPad 横竖屏及断网阅读做一次冒烟检查。系统化浏览器质检归阶段四，Gmail 自动发送归阶段六。当前用户仅授权本次文档交接，后续由 Build 接手开发。

阶段三的完成条件是从作者交稿到独立 HTML 全程可重复运行，且修订时身份与来源可追溯。已能渲染预制清单的样刊只覆盖这条链路的后半段。
