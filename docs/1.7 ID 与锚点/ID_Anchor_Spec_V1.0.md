# 栏目、文章 ID 与锚点规范 V1.0（定稿）

ID 用来辨认同一个内容对象。锚点是读者打开 HTML 时可以跳到的位置。栏目或文章换标题、调顺序、移到同一期的另一个栏目后，已经发出的链接仍应指向同一个对象。

## 命名与范围

每期以归档日期和固定 HTML 文件名定位。以下以 `Daily_Input_2026-11-06.html` 为例。同一文件中的 ID 全部唯一，跨期定位使用“文件名 + # + ID”。栏目 ID 在这里标识当期的栏目实例；跨期关联同一栏目属于归档元数据。

| 对象 | 首次分配的 ID 示例 | 链接落点 |
|---|---|---|
| 栏目 | `sec-001` | 栏目的 h2 |
| 文章 | `art-001` | 文章的 h3 |
| 需要单独链接的小节 | `sub-001` | 文内 h4 |
| 图片、表格、代码或引文 | `mat-001` | 整个材料 figure，含说明与出处 |
| 材料的本地出处摘录 | `src-mat-001` | 对应的摘录；返回链接指回 `#mat-001` |

同一材料有多份本地摘录时，第一份使用上表的 ID，此后追加 `-002`、`-003` 等稳定后缀，删除后保留已用后缀。公开资料沿用稿件给出的外部 URL。只有需要定位或返回的内容才创建相应链接；这些代号不出现在可见标题中。

各类对象独立编号，从 001 开始，超过 999 后自然扩展为 1000。编号只表示首次分配的次序。比如第二篇被移到第一篇前面，仍使用原来的 `art-002`。每个日期的同一期修订沿用归档文件名；附件另存改名后，文件内的 `#…` 仍可跳转，其他文件指向旧文件名的链接则依赖原路径。

## 原稿怎样与 manifest 对应

建议由入库程序在出版工作副本中写入不可见标记。标记是单独一行的 HTML 注释，放在对象之前，与前后块各隔一个空行。只识别顶层 Markdown 块中的这一种标记。标记连同其后的对象一起移动；文章标题后的体裁、来源两个字段仍按 1.5 紧接标题。原始交稿文件保留原貌。

```markdown
<!-- id: sec-001 -->

## 技术方法

<!-- id: art-001 -->

### 当日志装不进内存

体裁：讲解综述

来源说明：《每日信息输入》项目样文。120 GB 为假设输入量。

凌晨两点交班时，值班同事留下了一个问题。
```

同一期 manifest 保存已分配的 ID、对象类型、父子关系和保留停用的编号。上例中文章记录的父栏目是 `sec-001`。工作副本上的标记用于找到正文，manifest 用于核对身份及维护编号历史。HTML 直接使用已登记的 ID；指向上例文章的页内链接为 `#art-001`。渲染时读取已提交的一对工作副本和 manifest。

## 首次出版、修订和旧样张

- 首次接收没有标记的稿件时，在工作副本中为栏目和文章分配 ID，再按需登记小节和材料。既有标题、空格、语言和标点原样保留。
- 修订从上次已登记的工作副本开始。改题保留 ID；移动保留 ID 并更新父项与显示顺序；复制成另一篇时分配新 ID。新增对象从历史最大编号往后分配，删除的编号留档。并发分配按期串行；工作副本和清单作为一版一起提交。重试同一版直接复用已提交映射。
- 若替换稿丢失标记，遇重名或身份不明时列出待配对项，由校对确认后再出版。正文相似度、标题和显示位置只用于辅助校对。
- 回读已发布的旧 HTML 时，先导入真实使用过的 ID，例如 1.4 的 `requests`、`processing` 和 1.6 的 `material-1`、`excerpt-1`。在该旧文档的重出版中，将这些值登记为既有对象的固定 ID，按原值生成目标和返回链接。新对象使用新格式。旧文件里还没有锚点的文章可在工作副本中补发。旧附件的局部编号不可直接拼入同一文件；合并为新一期时重新映射局部链接，保留原归档。

## 验收

交付前检查整页 ID 唯一、前缀与对象类型匹配（已登记旧 ID 除外）、父栏目及父文章存在、每个页内链接恰有一个目标，出处摘录的返回链接回到发起它的材料。代码围栏、引用里的示例标记按内容处理。未知 ID、重复标记、悬空标记或断链应报告期次、所属文章及位置。正式出版引擎的实现归入阶段 3。

本轮用临时样例验证同名文章换序、一篇改题并跨栏、材料与摘录往返、旧样张中的定位符及断链和重复 ID 的识别。以上为规则级验证。
