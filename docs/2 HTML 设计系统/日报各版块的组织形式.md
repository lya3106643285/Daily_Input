# 日报各版块的组织形式 · 工作稿

本稿以已通过 iPad 试读的 10 月 31 日版为参照。两组九栏来自原刊；下表把该期实例整理为可复用的编排建议。每期选题、篇数、段落顺序及媒体数量由稿件决定。表内的阅读问题供编辑使用，不作为读者可见的固定小标题。

## 基础组件

- **文章**用原题和正文构成，可另带摘要、题下来源、篇末来源。正文依次容纳段落、文内小标题和材料。按独立文章分篇；同一论证的几个步骤通常放在同一篇内。
- **材料**可选图片、表格、代码或直接引文。图注告诉读者看什么，材料出处紧贴这项材料。文章级来源可以同时存在，例如一篇游戏机制解读在篇末列开发者访谈，文中截图单独标注发行商。
- **栏目**由稳定的栏目身份、当期主题、可选导语和文章列表组成。目录和栏内共用同一个定位目标。目录摘要概括当日选题，实际篇数由文章列表得出。

[文章组件](../../templates/components/content.html.j2)提供独立的题下和篇末来源位置。正式整期按版别选用位置：A 版的新闻摘要与新闻解读均在标题下列出文章来源，B 版的长期输入统一在篇末列出。原稿的来源字段写法见 [1.5 规范](<../1.5 Markdown 原稿规范/Markdown_Content_Spec_V1.0.md>)执行。[媒体组件](../../templates/components/media.html.j2)负责图注、替代文本、出处和可选摘录。

## A · 今日动态 / 新闻层

| 版块 | 一栏如何组织 | 什么时候用材料 |
|---|---|---|
| AI 前沿 | 按独立进展分篇。开头交代谁在何时发布了什么，再解释与此前相比的变化，并标明已宣布、已开放或已有独立验证等实际状态。 | 对比模型或实验时附同口径表格；政策变化可引用关键原文。 |
| 硬件、图形技术与价格 | 先让读者辨明讨论对象和比较基准。技术稿沿瓶颈、改动、实测条件展开；行情稿列明时间、地区、规格和价格口径。 | 有同口径数字时用表；涉及渲染机制时插入能解释变化的图。 |
| 科技与游戏事件 | 通常一事一篇，把事件经过、当事方披露和影响分开。几件事若只是同日发生，可以各成短文。 | 时间次序影响理解时列时间线，存在争议时并列可核验的原话。 |

## B · 每日长期输入层

| 版块 | 一栏如何组织 | 什么时候用材料 |
|---|---|---|
| 论文精读 | 围绕研究问题写一篇连贯解读。由一个例子引出方法，再用实验条件说明结论能推广到哪里。 | 公式、算例、论文图表放在第一次需要它们的位置，标注原始页码或图号。 |
| GitHub 经典项目 | 以项目为阅读单位。从它解决的实际问题进入，挑一条核心执行路径，给出读者能跟着走的源码入口。 | 引用具体版本、文件或函数；短代码块只保留理解这条路径所需的部分。 |
| GitHub 特殊新项目 | 从值得关注的新想法进入，交代目前能运行什么、依据什么、还缺什么验证。 | 演示结果和项目方设想分别说明；有复现材料时给出版本及入口。 |
| Gaming 技术解读 | 围绕一个机制或工程问题展开。先呈现玩家能观察到的现象，再解释实现、取舍与证据。一款游戏可串起多个小节。 | 示意图适合说明系统关系；实机截图适合展示可见效果，技术论断另附开发者资料。 |
| 游戏推荐 | 通常每款一篇。从一个具体游玩片段引出核心体验，说明什么玩家可能喜欢、哪类门槛值得预先知道。 | 选能展示正文所述体验的实机画面；有多款时，各图归入对应游戏。 |
| 每日好图 | 先确定可使用的作品与原图。开篇附近放完整构图和作品信息，再引导读者观察具体位置，最后展开解释。 | 原图是本栏的核心材料。局部图按需要追加，标明裁切位置，并保留原作出处。 |

例如同一期写到《Teardown》两次，技术栏可以从「玩家中途加入后，怎样恢复已被破坏的世界」展开；推荐栏可以从「拆出一条近路如何改变一次撤离」展开。二者都用同一套标题、段落和材料组件，稿件各自回答一个问题。
