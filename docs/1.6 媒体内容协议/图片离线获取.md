# 图片离线获取与交稿

实现：`src/publisher/images.py`。只在接收作者稿件时联网；出版与读者打开 HTML 时不需要下载图片。

## 获取方式和边界

来源不限网站：编辑通过官方 API、原始作品页、图库或官方媒体包确认具体图片后，将单张 PNG、JPEG 或 WebP 的 HTTP(S) 直链放入 Markdown。普通文章 URL 只用作出处，不作为图片文件下载。引用式 Markdown 图片也支持；代码块中的示例图片不会被下载。

本组件负责“已选图 → 下载 → 离线素材 → 交稿”，不负责搜索、从任意网页猜测正文配图、解压媒体包、绕过登录或自行判定许可。API 的检索和授权字段核对属于选图阶段；不同来源最终交付同一种直链及许可记录。没有适用的离线刊用许可时，只保留作品文字和原网页链接，不放图片材料块。要求热链接的平台不能直接进入本流程。

## 作者输入

沿用媒体协议：独立图片段落后接图注、材料出处。

```markdown
![作品画面内容](https://images.example.org/picture.png)

图注：读图条件和内容。

材料出处：作者、作品以及适用范围。
```

在原有 `issue.json` 上新增 `remote_images`，键为 Markdown 解析后的图片直链。每个远程图片都需要一项；所有许可记录校验通过后才开始联网。

```json
{
  "remote_images": {
    "https://images.example.org/picture.png": {
      "source_url": "https://example.org/work",
      "author": "作者或机构",
      "title": "作品名",
      "license": "CC0",
      "license_url": "https://creativecommons.org/publicdomain/zero/1.0/",
      "rights_verified_on": "2026-11-07",
      "allow_offline": true,
      "changes": "可选：裁切、改绘或标注说明"
    }
  }
}
```

`allow_offline` 是编辑核验结果，必须为 JSON 布尔值 `true`。下载器不会把该字段当作授权事实的独立证明，也不会自动判断许可证的全部条件。署名、作品、许可链接、出处、核验日期和改动说明会补入原有材料出处，在 HTML 中随图展示。输入中的原有出处与说明保留。

## 运行和 pipeline 接口

在项目的 Python 环境运行：

```sh
python -m publisher.images author.md --metadata issue.json --output-dir var/prepared/2026-11-07-v1
python -m publisher.ingest var/prepared/2026-11-07-v1/draft.md --metadata var/prepared/2026-11-07-v1/issue.json --store var/issues --output-dir outputs/production
```

Python 接口为 `publisher.images.prepare(author, metadata_path, destination, ...)`，返回准备包目录的 `Path`。pipeline 应在图片准备成功后调用现有 `ingest`；本组件不发送邮件、不运行视觉检查。

准备包：

- `draft.md`：图片替换为 `assets/<sha256>.<实际格式后缀>`，保留原有图注，补全展示用署名和许可。
- `author-original.md` 和 `metadata-original.json`：原始文件按字节保留。
- `issue.json`：原有元数据加 `image_localization`，包含原稿、工作稿、原始元数据的 SHA-256，以及每个远程图片的下载凭据。
- `assets/`：完整原始图片字节；原有本地图片也会校验并复制，不能越出作者目录的 assets。

下载凭据包含请求 URL、最终 URL、重定向链、抓取时间、响应类型、字节数、宽高、SHA-256、本地路径和原有许可字段。入库核验文件哈希，将记录写入 `manifest.asset_records[path].downloads`；保留原稿为 `original.md`，本地化稿为 `author-localized.md`，全部随 READY 校验。出版引擎继续制作内嵌图片的单文件 HTML。

输出目录必须不存在，失败会清理本次临时目录，已有交稿包不会被覆盖。重跑已完成的期次时直接复用交稿包并调用 ingest，避免重新抓取变化的 URL。同 URL 在一次准备中只下载一次；不自动重试失败请求，不自动替换图片或静默删图。若需重新获取，使用新准备目录，并按现有规则升级 version。

## 下载限制

默认最多 30 个图片材料、单文件 8 MiB、本期累计 40 MiB、单图 2500 万像素；只接受静态 PNG/JPEG/WebP。对响应类型、实际格式、完整解码和动画状态分别检查。CLI 支持 `--max-images`、`--max-bytes`、`--max-total-bytes`、`--max-pixels` 和 `--timeout`。成品 HTML 仍受出版引擎的独立文件大小限制，原图无需手工缩小。

每张图片默认 20 秒 I/O 预算，重定向最多 4 次；系统 DNS 解析时间由系统解析器控制。仅允许 HTTP(S) 和 80/443 端口，拒绝 URL 凭据、HTTPS 降级、非公网地址，以及 IPv4 映射/隧道地址；DNS 返回混合公网和内网结果时整次拒绝。实际 socket 连接固定到已检查的 IP，TLS 仍核验原主机名。每跳重新检查目标，不使用环境代理、浏览器 cookie 或登录凭据。HTTP 403、429、超时、错误类型、文件过大、许可缺失均导致准备失败，由编辑处理。

## 验证

```sh
python -m unittest discover -s tests -p test_image_localization.py -v
```

测试覆盖许可前置校验、内网地址与重定向、固定连接地址、大小和像素限制、引用式 Markdown、代码块隔离、已有目录保护、失败清理、原稿保留、下载凭据防错配，以及入库后离线 HTML 与重复入库。
