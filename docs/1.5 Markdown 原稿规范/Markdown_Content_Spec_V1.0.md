# 每日信息输入 · Markdown 原稿规范 V1.0（定稿）

用于把一期 UTF-8 Markdown 原稿交给出版程序。栏目、题名、段落、正文次序及出处以原稿为准。研究与写作沿用《每日信息输入》V3.2 的内容约定。本文只规定如何识别和呈现这些内容。

日常写作从[两版九栏原稿骨架](../../templates/每日信息输入_写作骨架.md)复制一份。入库程序负责生成清单、维护 ID 和工作副本。

## 一期的结构

| 原稿写法 | 出版含义 |
|---|---|
| `# 刊名` | 文件从唯一的一级标题开始。 |
| `## 栏目原名` | 开始新栏目。栏目导语如有，写在栏题与第一篇文章之间。篇数由程序统计。 |
| `### 文章原题` | 开始一篇独立文章，归入最近的栏目。下一篇、下一栏或文件结束时，本篇结束。 |
| `#### 文内小标题` | 当前文章内换节；适用于任一体裁。 |
| 一段文字，空一行再写下一段 | 输出自然段。字体、颜色、缩进、行高和留白由模板统一处理。 |

标题用行首井号加半角空格，按 Markdown 块结构解析。代码围栏或引用内部的标题不会开启新文章。正文中普通换行属于同一段；需要分段时用空行。

## 每篇只交接一次体裁与出处

每个三级标题后紧接一个独立段落，写 `体裁：新闻摘要` 或 `体裁：讲解综述`。接下来写一条或多条 `来源说明：…`，每条各占一个 Markdown 段落。字段名和全角冒号按此拼写，中英文文章通用；来源名称、原题和正文保留原语言。连续来源段结束后进入正文。字段只在这个开头位置识别。

原稿把来源集中在文章开头，便于编辑一起核对。正式日报发布时隐藏体裁字段，并按文章所属版别安排来源：A 版新闻摘要与新闻解读均放在题下、摘要和正文之前；B 版长期输入放在篇末。独立组件校样没有 A/B 版别时，沿用 1.4 的体裁对应位置：

| 体裁 | HTML 中的位置 |
|---|---|
| 新闻摘要 | 题下、首个正文段落之前。 |
| 讲解综述 | 本篇正文结束处，下一篇或下一栏之前。 |

例如，一条来源可写成 `来源说明：作者或团队 · [材料原题](原始网址)；该材料支持的具体内容。` 正式稿填真实资料；没有公开网址的记录可给出能定位原件的记录者、日期和文档名。构造案例要标明性质，实际引用的项目与案例说明可以分条写。正式稿缺出处时写“待补”，进入校对队列。体裁由交稿方显式指定，栏目名和文章字数均不参与判断。

## 交接与校验

- 一期一个 Markdown 文件，日期、期次及资源清单与项目的 manifest 配合使用。同一篇正文只维护一份。版式变更时可复用原稿。
- 检查唯一刊名、标题父子关系、每栏至少一篇、每篇至少一段正文。检查每篇只有一个有效体裁且来源可定位。缺失、重复或顺序错误的字段应报告所属栏目、文章及行号，由校对修正后出版。
- 历史原稿缺少体裁或来源时，先在工作副本补录，保留归档原件。媒体、引文及详细来源标记在 1.6 定义，稳定 ID 与锚点在 1.7 定义。
- 完整示例见[两栏三篇原稿](两栏三篇示例.md)。已用 Markdown 解析器核对 1 个刊名、2 个栏目、3 篇文章、6 个文内小标题和 30 个正文段落，文章题名、段落文字与参考链接逐项对应 1.4 样张。本次校验覆盖原稿结构；出版引擎的渲染验收属于阶段 3。
